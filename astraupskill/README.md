# WW19 workflow-run idempotency course

This course follows [workflow-run-service.ts](../src/services/workflow-run-service.ts) and its `startWorkflowRun` entrypoint. The function looks up an idempotency key scoped by the initiating user, resolves the active workflow version, parses the definition, creates the run in a transaction, seeds execution after the transaction completes, and reloads the run for the caller. The expanded runtime lab executes that real service through five cases: same-user replay with a different payload, different-user creation with a distinct scoped key and exact create payload, missing version, parse failure before transaction, seed failure after creation followed by replay, and missing post-seed reload.

The important boundary is temporal: the transaction ends before `seedRunExecution` begins. A seed failure therefore leaves a created run, and a retry finds the same user-scoped row without reseeding. Read the test and source before practice. The lab does not prove database uniqueness under concurrent creates, because the adapter is sequential and the schema/provider are not live. Chapters teach identity versus payload, transaction scope, error ordering, traces, exercises, separate answers, and limits. Run the exact command in VERIFICATION.md from the project directory.
